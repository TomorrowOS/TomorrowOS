# Changelog

All notable changes to TomorrowOS are documented in this file.

TomorrowOS ships two versioned surfaces:

| Surface | Package / artifact | Current version |
| --- | --- | --- |
| **TomorrowOS SDK** | `@tomorrowos/sdk` (npm) | 1.1.8 |
| **Player app** | Tizen `.wgt` + BrightSign + Windows | 1.0.0 (+ Windows player) |

Versioning notes:

- The **player** uses one product version across supported platforms (Tizen, BrightSign, and Windows). New platforms join the same line (for example 1.1), rather than starting a separate `webos-1.0`.
- The **SDK** follows its own semver on npm and may move faster than the player.
- Pin SDK versions in production.

---

## 2026-11-09 — SDK 1.1.8

**SDK:** `@tomorrowos/sdk@1.1.8`

### SDK 1.1.8

- Screen tags and per-screen references now live in the CMS database (SQLite, Postgres, and the memory store)
- An existing `screen-tags.json` or `screen-references.json` is imported once, then renamed to `*.json.imported`
- Store export, import, and migration include tags and references

---

## 2026-11-07 — SDK 1.1.7

**SDK:** `@tomorrowos/sdk@1.1.7`

### SDK 1.1.7

- Per-screen references: string key/value pairs for one screen, up to 32 keys
- Each `setPolicy` for that screen includes its references. The shared playlist is unchanged
- HTTP routes: `GET /screen-references`, `GET` and `PUT /device/:id/references`, `DELETE /device/:id/references/:key`
- Saving or removing a reference pushes the latest policy to that screen
- The default Control Panel does not edit references; a product UI calls these routes

---

## 2026-10-31 — SDK 1.1.6

**SDK:** `@tomorrowos/sdk@1.1.6`

### SDK 1.1.6

- Screen tags. A playlist item can require `any`, `all`, `notAny`, or `notAll` of a screen’s tags. No rule means every screen
- Per-item schedule: start and end date, start and end time, and weekdays (Monday through Sunday). No schedule means all the time
- Tag rules and item schedules are removed before the player receives the policy
- Control Panel: manage tags, filter screens by tag, and set a rule and schedule on each playlist item
- Delete a playlist that is not assigned to a screen
- HTTP routes for the tag catalog, a screen’s tags, and a playback preview of what that screen will play

## 2026-09-15 — SDK 1.1.4 + Windows player

**SDK:** `@tomorrowos/sdk@1.1.4`  
**Player:** Windows player (download from the Control Panel)

### SDK 1.1.4

- Optional **CMS password** (`CMS_PASSWORD`) to lock the Control Panel login
- Replit / Vercel (v0) setup guides ask for optional CMS password during setup (Q4)
- Password protects the Control Panel only — device WebSocket / pairing / uploads stay reachable

### Windows player

- TomorrowOS **Windows** player is available
- Download it from the CMS Control Panel → **Download Players**

## Initial release — 2026-07-28

**SDK:** `@tomorrowos/sdk@1.0.0`  
**Player:** TomorrowOS Player **1.0.0** (Tizen + BrightSign)

First public baseline of the open-source digital signage foundation: a CMS server SDK, on-device players, and a shared `device.*` command surface.

### Added

#### TomorrowOS SDK (`@tomorrowos/sdk` 0.9.70)

- `TomorrowOS` server: HTTP + WebSocket `listen()` for your own CMS
- Device pairing (`pairing.verify` / `pairing.unpair`) and online / offline presence
- Playlist catalog: save, retire, assign, publish, and clear device assignments
- Content policy push via `device.content.setPolicy` / `device.content.clear`
- Media upload helpers and publish-time asset reachability checks
- Device helpers: rename, on/off timer, reboot, screenshot, logs, capability query
- Stores: memory, SQLite, Postgres / Supabase-style backends
- Control Panel starters and hosting guides (Replit, Vercel / v0)
- Player download helpers (including BrightSign zip with CMS URL baked in)

#### Player app (1.0.0)

- Unified player line for **Samsung Tizen 6.5 and 7.0** and **BrightSign**
- On-device pairing code and CMS connection
- Playlist playback for images, videos, and widget `.zip` / `.wgt` items
- Local media cache and offline / reboot resume behaviour
- Black-gap-aware handoffs between images and videos
- Brand idle fallback when nothing playable is active
- Shipped wire commands:
  - `device.info.get`
  - `device.info.getCapabilities`
  - `device.content.setPolicy`
  - `device.content.clear`
  - `device.power.reboot`
  - `device.display.setOnOffTimer`
  - `device.telemetry.captureScreen`

#### Documentation

- Beginners guide, developer guide, API overview
- Assets / atomic activation, widget ZIP, black-gap playback guides
- Tizen and BrightSign platform pages
- Certification guide for model + firmware evidence

### Known issues

- **Tizen:** `device.telemetry.captureScreen` needs commercial firmware **1080+**
- **BrightSign Series 3:** upgrade firmware to **9.1.140+** for reliable video playback
- **BrightSign Series 3:** **4K H.264** is a hardware limit — use 1080p H.264
- webOS and Android players are not shipping in this initial player line yet

### Notes

Treat this release as the **initial** SDK + player baseline for documentation, certification, and production pinning:

```bash
npm install @tomorrowos/sdk@1.0.0
```

Player installs report `playerVersion: "1.0.0"`.
